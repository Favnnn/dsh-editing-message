# dsh-editing-message — правка и перегенерация сообщений для DeepSeek Harness

Плагин для web GUI DeepSeek Harness: под **каждым сообщением пользователя**, рядом
с кнопкой «Копировать», появляются ещё две кнопки-иконки:

1. **Редактировать сообщение** (карандаш) — сообщение превращается в редактор.
   После «Сохранить и отправить» чат **продолжается с этого места**: модель
   «забывает» всё, что писала после этого сообщения, и отвечает заново уже на
   **изменённый** текст — в том же чате.
2. **Перегенерировать** (круговая стрелка) — то же, но без правки: сообщение
   отправляется повторно, модель отвечает заново.

- **Плагин:** `dsh-editing-message` 1.0.3
- **Harness:** dsh-v0.2.0-rc.2 (официальная доставка бандлов)

## Как это работает (семантика «забывания» и «того же чата»)

История сессии в Harness — это только дополняемый журнал событий: редактировать
задним числом существующую сессию нельзя (и это правильно — журнал единственный
источник истины). Поэтому обе кнопки используют **официальный механизм ветки**
(тот же, что у штатной кнопки «ветка» под ответами), автоматизированный до
«продолжения того же чата»:

1. Плагин вызывает `sessions.fork({ sessionId, atSeq: N })` — создаётся
   **продолжающая сессия**, наследующая историю **до** выбранного сообщения
   (событие `atSeq` исключается). Всё, что было после — старый ответ модели и
   последующие ходы — в продолжение не попадает.
2. В продолжение отправляется новый текст (`session.prompt(content, 'queue')`):
   изменённый — для «Редактировать», исходный — для «Перегенерировать».
3. Продолжение открывается (`uiWorkspace.openSession`), а **исходный чат
   архивируется** (`uiWorkspace.archiveSession(id, { stopActivity: true })`).

Почему это выглядит как «тот же чат»: продолжение наследует **тот же заголовок**,
а сайдбар ставит новую ветку **прямо перед её источником** (документированное
правило упорядочивания форков). После архивации исходника в списке остаётся одна
строка на прежнем месте — визуально чат продолжился. Исходник со старыми
ответами не удаляется: он доступен в фильтре «Все диалоги (показать архивные)»,
и его можно вернуть кнопкой «Разархивировать». Если у исходника была незавершённая
работа и архивация запрашивает её остановку — запрос тоже отправляется;
при отказе хоста оба чата просто остаются в сайдбаре (ничего не теряется).

Нюансы:

- Правка/перегенерация **старого** сообщения отбрасывает в продолжении всё
  после него (включая более поздние ходы) — это и есть запрошенная семантика
  «модель забывает свой ответ и отвечает заново».
- Вложения (картинки/файлы) в v1 не переносятся: повторно отправляется только
  текст сообщения (браузер больше не владеет исходными байтами вложений).
- Для сообщений, отправленных в середину хода (steering), работают те же кнопки.

## Установка

Требуется: установленный harness (клон репозитория с выполненным `pnpm install`).
`%DSH_HOME%` по умолчанию `C:\<пользователь>\.dsh`, учитывается переменная
окружения `DSH_HOME`.

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

или двойной клик по **`install.bat`** (cmd-обёртка, держит окно открытым).

Установщик самодостаточен (сам находит чекаут harness; путь можно задать
`-HarnessRoot`) и делает строго по порядку:

1. Снимает legacy-зависимость `link:` от этой папки, если её оставил
   plugin-manager (перенос папки не должен ломать работающий плагин).
2. Удаляет legacy-копию из `%DSH_HOME%\plugins\` (старая схема), если есть.
3. Упаковывает папку в tarball (`pnpm pack`) и ставит бандл официальным CLI из
   чекаута: `pnpm dsh plugin --profile web add <файл.tgz>`. Ничего в файлах
   профиля вручную не пишется.
4. Чистит артефакты **точечно**: только точный путь устаревшего артефакта той же
   версии и точный путь ранее упоминавшегося в манифесте tarball'а этого же
   пакета. Никаких масок и нецелевых удалений.

После установки **перезапустите `pnpm dsh web`** и обновите страницу (F5). Первая
регистрация нового бандла в реестре клиентских модулей происходит при старте
сервера — одного F5 недостаточно (эталонный dsh-agents-board документирует то же
самое). Дальнейшие включения/выключения на странице Plugins — без рестарта.

Повторный запуск безопасен и идемпотентен. Изменили `client.js` / `index.js` в
мастер-папке — снова запустите `install.ps1`, затем рестарт сервера. Нюанс pnpm:
при **той же версии** пакета профиль может остаться со старой копией из своего
store — установщик сверяет хэш копии с исходником и громко предупредит; в этом
случае поднимите `version` в `package.json` и запустите установщик ещё раз.

Мастер-папку можно свободно перемещать: профиль держит собственную копию
(tarball-установка через `file:`-артефакт, а не ссылку на папку). После переноса
ничего делать не нужно; правки кода — запуск `install.ps1` уже из нового места.

## Удаление

```powershell
powershell -ExecutionPolicy Bypass -File uninstall.ps1
```

или двойной клик по **`uninstall.bat`**. Скрипт снимает бандл официальным CLI
(`pnpm dsh plugin --profile web remove dsh-editing-message` — CLI убирает
dependency, список бандлов, копию из `node_modules` и overlay-ряд), удаляет
legacy-копию и **точный** артефакт, на который ссылался манифест профиля.
Мастер-папку не трогает. После удаления — рестарт `pnpm dsh web`.

## Отказоустойчивость

Если плагин сломается, Harness запускается без него:

- **host-половина** (`index.js`) — пустой `apply()`, бросить нечему;
- **клиентская активация** (`apply`) обёрнута в try/catch: падение гасит только
  плагин, а не страницу (веб-оболочка считает фатальным только необработанное
  отклонение активации);
- **регистрации слотов** — каждая в своей try/catch («safeInject», как
  `safeSlot` в dsh-agents-board);
- **рендер строки** обёрнут в React-граничный класс (`SafeBoundary`): сбой
  отрисовки одного сообщения деградирует его до простого запасного бабла, а не
  опустошает слот;
- **сервисы** (`sessions`, `uiWorkspace`, `slots`, `locale`) читаются мягко,
  через `ctx.get(...)` с проверкой: нет нужного сервиса — плагин просто
  бездействует, штатный рендер сообщений не тронут;
- **действия** (fork/prompt/open) — каждая в try/catch с сообщением об ошибке
  в строке; повторный клик во время операции блокируется (busy-набор);
- в слот плагин пишет только через `ctx.slots.inject/register` — DOM вне своих
  компонентов не трогает.

Кнопки появляются только когда доступны нужные API (`sessions.fork`,
`sessions.using`); иначе регистрация не выполняется и остаётся штатный рендер.

## Как устроено

| Файл | Роль |
|---|---|
| `package.json` | манифест бандла: `dsh.bundle.patch`, `dsh.client` (platform web, immediately), экспорты `.` и `./client` |
| `index.js` | host-половина: пустой `apply()` — весь функционал клиентский |
| `client.js` | клиентский бандл (формат `window.__ModuleLoader__`): рендер сообщения + кнопки, редактор, fork/prompt/open |
| `cordis.patch.yml` | overlay-патч бандла: ряд `id: editing-message`, `name: dsh-editing-message` (без config) |
| `install.ps1` / `install.bat` | установка: pack → официальный `dsh plugin add` → точечная чистка артефактов |
| `uninstall.ps1` / `uninstall.bat` | удаление: официальный `dsh plugin remove` + точечная чистка |
| `README.md` | этот файл |

Точка монтирования UI — слот **`conversation.chat.node`** с ключами `user` и
`steering`. Ключ переиспользуется через **приоритетную тень**: штатный рендерер
занимает ячейку на приоритете 0, а повторная регистрация того же ключа на том же
приоритете бросает ошибку, поэтому плагин регистрируется на приоритете −1
(с запасными −2…−6) — рендерится запись с **наименьшим** живым приоритетом в
ячейке. Выключение/удаление плагина возвращает штатный рендер автоматически.
Состав ключей подтверждён через `cordis_inspect_query Slots.listSubTree`. Вид
сообщения воспроизводится собственным кодом плагина: та же геометрия и токены
темы (`--dsw-specific-bubble`, `--dsw-radius-xl`, `--dsh-content-font-size`…),
свои иконки, свой clipboard (с запасным `execCommand`-путём), такое же скрытие
действий старых сообщений по hover (CSS `:has(~)` — копия правила хоста).

Действия идут через публичные клиентские API:

- `ctx.get('sessions').fork({ sessionId, atSeq })` — ветка до сообщения;
- `sessions.using(childId, …, ref => ref.binding.session.prompt(content, 'queue'))` —
  отправка текста в ветку;
- `ctx.get('uiWorkspace').openSession(childId)` — открыть ветку.

## Диагностика

- **Кнопок нет** — перезапустите `pnpm dsh web`, затем F5. На странице Plugins
  проверьте, что бандл `dsh-editing-message` включён (родной тумблер ряда).
- **В консоли браузера** строка `renderer installed for key "user"` — регистрация
  прошла; префикс `[editing-message]` на прочих строках — отказоустойчивые
  деградации (плагин продолжает работать или бездействует, страницу не роняя).
- **Правил client.js — ничего не поменялось** — рантайм читает копию профиля:
  запустите `install.ps1` заново, затем F5 (правки host-половины — с рестартом
  сервера). Установщик сверяет хэш копии с исходником и предупредит, если pnpm
  переиспользовал старую копию той же версии — тогда поднимите `version`.
- **Удалил мастер-папку** — сервер не пострадает: профиль держит собственную
  копию. Верните копию запуском `install.ps1` из любого места, где лежит папка.
